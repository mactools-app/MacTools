# Preferences Backup

Preferences Backup transfers supported configuration between installations and channels. It does not clone a Mac or restore every local database. Export a fresh backup after installing plugin versions with this support: an older backup cannot recover settings it never contained.

The export sheet lists the selected plugins and their exclusions. Expand coverage details before exporting. A selected plugin that fails to export blocks saving the file until it succeeds or is deselected. Automatic, cloud, and pre-import safety snapshots keep the last good backup when any selected exporter fails. An unavailable plugin is distinct from a plugin with no portable settings.

Manual import replaces the selected preference categories. Missing and unselected plugin sections preserve destination settings. Selecting Shortcuts replaces the entire shortcut category: bindings omitted from the backup return to defaults, including local Clipboard item and excluded prompt bindings. Leave Shortcuts unselected to preserve existing bindings. Cloud sync separately preserves omitted machine-specific bindings. Restore results distinguish saved configuration, configuration needing permission, unavailable plugins, deferred imports, and failures. The whole import is not one transaction: unrelated sections may succeed when another fails. Source coverage annotations are informational; they cannot authorize a restore or create a missing payload.

## What transfers

The [generated inventory](preferences-backup-inventory.md) accounts for every source plugin. `portable` means the declared configuration transfers; `partial` lists exclusions; `localOnly` deliberately keeps its state here; `none` has no ordinary portable configuration; `unsupported` declares an unsupported boundary. Runtime results reconcile the installed package with the actual provider, rather than substituting current catalog claims for an older installed binary.

- Window Layouts transfers behavior, modifier dragging, centered guides, preset selection, and custom layout identities. Import reconfigures the existing session without moving a window or applying a shortcut preset. Accessibility permission remains local.
- Auto Input retains rules and input-source identities, including unavailable sources. Import updates observers and HUD configuration; automatic input/function-key changes wait for the next actual application activation. Input Remapping keeps unsafe-trigger confirmations local.
- App Hotkey, Launchpad, and Right Click use application identities with paths relative to named installation roots. They validate the destination bundle without launching it. Missing apps retain their definitions and placement as unresolved; distinct copies retain distinct records. Launchpad keeps folder order and UUIDs. Window Switcher transfers stable manual bundle mappings and leaves process/window assignments local.
- AI Assistant and Translator transfer provider/model settings, including saved disabled drafts with incomplete fields. Drafts remain disabled after restoration; enabling them requires a usable configuration. Unsaved editor contents are not backed up. Unrelated preference imports preserve open Translator prompt and Launch Control note drafts; changed saved definitions refresh their editors. AI prompt saves must finish pending recovery before accepting edits. Structural bounds and credential-component exclusions still apply to every profile. Custom prompt text has a separate, persisted opt-in in each plugin's settings. It governs manual backups, automatic backups, and cloud sync. The destination's opt-in never changes on import. Omitted destination prompt text, including destination-only Translator templates, is preserved regardless of the destination export opt-in; a conflicting included record rejects the section instead of silently overwriting excluded private text. API keys never transfer. Local service saves validate every enabled provider before writing keys, then commit profile settings and endpoint grants together. Failures restore only previous grants backed by freshly verified unchanged effective credentials, including Translator’s legacy fallback; uncertain or changed writes stay unauthorized. Imported endpoints cannot reuse a destination key until local key setup authorizes that service.
- Launch Control transfers favorites using a named launch directory plus plist filename, without commands, raw plists, user IDs, or `launchctl` operations. Missing items remain metadata awaiting a match. Notes have a separate persisted opt-in. Unrecognized legacy paths stay local; excluded destination notes are preserved and conflicting incoming notes reject the section.
- Clipboard transfers retention/display/filter preferences. The remember-filters preference transfers; the last selected filter axes and window positions stay local. Its encrypted history, Saved library, content-dependent item shortcut definitions, collection state, and keyword activation are excluded from the portable archive. Import does not prune the library or start collection/expansion. Importing the Shortcuts category can still clear the excluded items' bindings under the replacement policy above. Retention deferral is destination-local and survives app relaunch. Ordinary later captures or explicit local retention edits resume normal retention behavior; unrelated UI changes preserve it. Failed deferral writes reject the import without applying shorter retention. Use the [dedicated clipboard archive](clipboard-backup.md) for content recovery.
- Display target modes, Calendar presentation, Device Battery preferences, Duo Status icons, Screenshot zoom behavior, Trackpad Scale auto-capture choice, and similar presentation settings transfer without importing readings, authorization, capture sessions, calibration, or hardware state.
- Battery Charge Limit transfers behavior parameters while inactive; it never activates charge control. Keep Awake transfers behavior without starting assertions or virtual displays. Active local sessions reject parameter restoration until stopped. App Volume preserves running playback during import and applies imported preferences when an app next starts playback or its audio processes change.
- Quit Protection transfers confirmation mode and timing, VoiceOver timing, feedback, and app scope and lists. Each Mac keeps its own enabled state and permission grants. App scope and both lists stay together on the current Mac if either list has an invalid bundle identifier or exceeds 512 entries. Removing those entries in Quit Protection settings makes the scope transferable again.
- Disk Clean roots, permanent-delete policy, and execution/recovery data remain local. Key Stats tracking consent and usage history remain local. Credentials, capture/access consent, OS permission grants, recovery journals, caches, and local activation policies are excluded throughout.

## Provider contract

Use existing `PluginPortablePreferencesProviding`, `PluginPortablePreferencesRestorationReporting`, and `PluginPersistentPreferencesChangeSignaling` hooks. Optional manifest metadata adds no PluginKit ABI requirement. Keep each payload independently versioned and bounded; the enclosing archive remains format 7 with its existing 16 MiB limit. Optional bounded diagnostics contain only plugin IDs, status codes, and exclusion codes; previous format-7 readers may ignore them.

Validate the whole section, including identifiers, counts, strings, finite numbers, enums, and URL/path boundaries, before mutation. Do not discover/export arbitrary storage keys. Preserve absent optional fields according to the version contract. Commit through a verified atomic file or an allowlisted transaction with rollback/recovery, preserving prior raw values and absent keys. Journal only fields being changed; untouched excluded data must not block unrelated transactions. Publish live state only after durable success. Recovery journals stay local and prevent incomplete state from being exported.

Reconcile imports through normal permission and conflict paths without prompting or triggering unrelated operations. Keep requested configuration when permission is denied. Emit a persistent-change signal only after a meaningful durable portable change, including edits from custom views; scans, sampling, live refreshes, and excluded-only changes do not count.

Open settings editors must reconcile their drafts after a durable restore, including cloud imports that keep the same record identities. Included disabled definitions retain both per-prompt recorder and Actions & Shortcuts bindings while remaining inactive. Preference-only imports that do not change definitions preserve open prompt drafts. Validate enabled configurations after merging any preserved destination text.

Definition providers additionally implement `PluginPortablePreferencesActionReferencesProviding` and `PluginActionReferenceBackupProviding`. Index exactly the included definitions. The host exports/restores dependent shortcuts, Run Links, workflows, Grid entries, and gestures only when the required definition payload succeeds and contains that reference. Action-surface providers export after definition providers. Classify content-dependent legacy shortcuts through the same backup-disposition hook; excluded Clipboard item references cannot masquerade as portable shared shortcuts.

Add `preferencesBackup: {"status": "partial", "exclusions": [...]}` to the canonical source manifest. Use the schema's stable codes, keep privacy declarations accurate, regenerate the inventory and website data, and run `make script-tests`. New consumers must satisfy the existing minimum-host inventory; do not bump the ABI for descriptive metadata or plugin-private codecs.

Keep compact tests for round trips, excluded/local-state preservation, invalid/future payloads, durable-write failure, and consequential runtime reconciliation. Use fake storage or temporary directories. Live desktop checks must use isolated identities and synthetic data; store tests do not establish real Accessibility or hardware behavior.

### On-demand desktop evidence

After a focused test build, run `scripts/testing/preferences-backup/run.sh` from an Accessibility-authorized terminal. It creates a new temporary evidence directory, synthetic preference suites, a target window, and a separate denied-permission app identity. It does not install, sign, publish, replace installed apps, copy user settings, or change permission grants. The granted check briefly moves the pointer over its owned window; run it while not interacting with the desktop.

The check covers actual modifier movement, centered-guide display and snap, relaunch persistence, denied-permission preservation, real host action dependencies, native export screenshots in four languages, an unresolved Right Click app row, accessibility labels, Return/Escape, and disclosure activation. Review the generated images and AX reports; ordinary Tab traversal follows the Mac's Keyboard Navigation setting. The on-demand XCTest is skipped during normal CI. Synthetic preference domains are removed on exit; evidence files remain for review.

Run `TEST_RUNNER_MACTOOLS_RUN_DESKTOP_TESTS=1 make test TEST_FILTER=InputRemappingModelsTests/testMountedEditorPreservesCloudRestoredRuleOnSubsequentToggle` to verify that an open Input Remapping editor retains a cloud-restored action after its next toggle. It uses a synthetic settings window and injected input services, with no global input events or live cloud transport.
